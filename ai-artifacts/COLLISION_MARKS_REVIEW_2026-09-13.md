## 3. Relaxation proposals endorsed

Only one, and it is the hooks-1 decision rather than a change of substance:

- **Relax ruling 2's stated guarantee to what a theory-level hook can deliver.** Verified: no hook on a theory *value* can delimit a PIDE re-execution of a command, because the header's exec is reused. The honest statement is: the marks are dropped whenever the theory is **begun again in this process** — a re-executed header, a changed import (`document.ML:839, 855`), an Isa-REPL or `Thy_Info` reload, a fresh batch load — and at theory end; a PIDE evaluation cancelled mid-theory and resumed does not re-begin the theory, so one stale mark can survive and cost at most one spurious four-line warning under ML_debugger. Benefit: the source stops asserting something false at `cache_file.ML:677` and `:918-921`, the hook keeps the work it genuinely does, and no code moves. This is consistent with the author's own "不用管。直接无视" on old/new PIDE versions of one theory.

Explicitly **not** endorsed, and worth naming so nobody re-proposes them: clearing the mark on a `rewrites = true` write (it would silence exactly the pA-vs-pC pair the alarm exists to catch); deriving the marks from `proofs`; stamping marks with `Context.theory_id` (does not discriminate the case it was written for, and costs a retained ancestor bitset per mark against ruling 3); reaching into PIDE `Execution` for an exec id (forbidden by standing repo rule, and a debugging aid is not worth it).

## 4. MUST_DISCUSS — options

### C1 (correctness) / E3 — the skipped write leaves no mark

`cache_file.ML:818-824`: when the incoming record equals the live one byte for byte, the function returns `((false, NONE), tab')`, so the write is neither compared nor marked, while `written`'s declaration (`:659-661`) says the table is "what THIS session has already written under each key". No current writer reaches the branch with a mark in play (I checked all five: `sledgehammer_solver.ML:1986`, `cache_file.ML:947`, `proof_store_AoA.ML:143`, `agent_server.ML:1964, :2187`), so **neither option changes any observable behaviour today**.

- **Option A — hoist the bookkeeping, single update site.** Bind `dirty` instead of `_`, compute `msg` and `w'` above the `if`, and make the branch decide only whether a frame is appended and the store updated:
  `((not live_and_identical, msg), Symtab.update (name, (c', dirty', w'), tab'))`.
  *Consequence:* `mark = SOME m` alone decides whether an id is checked and marked, so the declaration becomes true for every present and future caller; with the debugger off `w' = w` and the extra `Symtab.update` is on a table with one entry per open theory (free). *Risk:* a future writer that writes a file-loaded row back verbatim would then mark that id with the file's text, and the ordinary self-heal (replay fails → tombstone keeps `w` → re-search yields a different text) would print a collision warning for a plain cross-build update — precisely the false positive `:661-663` says the two-table split exists to avoid. Unreachable today, symmetric to the missed alarm it removes.
- **Option B — leave the code, sharpen the comment.** Append one clause to `:675-677`/`:795-797`: a write that leaves the live record byte-identical installs nothing, so it marks nothing either. *Consequence:* zero risk, the hottest path stays a pure `tab'` return, and the skip keeps meaning "nothing changed, therefore nothing to record". *Cost:* the invariant stays a sentence a future writer must read (the shape ruling 7 ranks lower), and today it holds only because of a property of unrelated control flow, documented in a comment in another repository (`proof_store_AoA.ML:139-140`).

Recommendation: **A** if the author weighs "the table means what it says" above "a no-op write records nothing"; **B** if the reverse. Either way, ruling 1 stays verbatim — `rewrites = true` yields `mark = NONE` and is untouched by both.

### hooks-1 — the at_begin hook and ruling 2's guarantee

- **Option A — keep the hook, correct the two comments** (the relaxation in §3). One-sentence edits at `cache_file.ML:675-677` and `:918-921`, plus the matching sentence in the plan at `:1235-1237`. No code change, no risk. Residual: one spurious warning per cancelled-and-resumed evaluation that re-proves an id with different text, under ML_debugger only.
- **Option B — make the mark self-validating on the obligation instead of on the session.** Put the obligation's `hash : Hasher.digest option` into the mark and suppress the warning when both hashes are `SOME` and equal: same obligation re-proved differently is a re-proof, not a key collision, whatever PIDE did in between. *Consequence:* the cancel case goes silent for the right reason, and the four tests keep passing (test 18 seeds a different hash; test 20 writes `hash = NONE` and falls back to the text digest). *Cost:* it widens the mark (against the spirit of ruling 3's economy), it weakens detection for the `hash = NONE` writers (`agent_server.ML:2187`, `proof_store_AoA.ML:143`), and it is new design in a debugging aid.
- **Option C — accept the behaviour and say nothing.** Rejected: the source would keep asserting a guarantee the code does not provide, which ruling 7 forbids.

Recommendation: **A**.

### E4 — `proof_mark` and the head

- **Option A — `Symbol.beginning proof_head_len (Symbol.explode text)`.** Deletes five hand-rolled lines including the duplicated `" ..."`, reuses Pure. *Visible consequence:* blanks inside the kept head render as single spaces and trailing blanks are trimmed — which is what makes "exactly four lines" (ruling 5) a property of the code rather than of today's writers happening to emit one-liners. Given `sledgehammer_solver.ML:1662`, that case is real.
- **Option B — keep the head verbatim and take the first line only** (`hd (split_lines text)` before truncation). Also guarantees four lines, keeps non-blank characters untouched, but is bespoke code where Pure already has a diagnostics function — i.e. it trades ruling 7's reuse for a narrower change to the printed text.
- **Option C — no change.** The head stays byte-verbatim; a collision on an `all_auto` composite proof prints a warning longer than four lines.

Recommendation: **A**. It is the only option that satisfies both ruling 5 and ruling 7, and the sole thing the author needs to sign off is that a newline or tab inside the first 120 symbols now shows as a space.
